The walls keep leaking

A sandbox is the wall between an AI agent and everything else on the machine: your files, your keys, your network. Researchers keep finding holes in it. Between July and September 2026 alone, they published at least five separate escapes in popular coding agent tools.

Most of them didn’t need a clever prompt. A project’s own settings ran a command outside the box. An agent wrote a file that its unprotected host ran later. A sandbox could be switched off from inside.

Those are plumbing bugs, and plumbing can be tested directly. That’s what Husk does.

What Husk checks

Four walls. If any one of them fails, a hijacked agent can do real damage.

Files

Can the agent read or change anything outside its workspace, like your SSH keys or your other projects?

Network

Can it send data out to the internet, or reach services on the machine that it should never touch?

Secrets

Does it ever get its hands on a real password or token, or only on stand-ins that are useless if stolen?

Its own controls

Can it switch off its own restrictions, or leave something behind that runs later, outside the box?

How it works

1
Run it inside the box

Start Husk in the same sandbox your agent uses, on your own machine or in your build pipeline.

2
It tries every known way out

Each check copies a published escape and tries it directly. There’s no AI model in the loop, so a pass means the wall held, not that the agent just wasn’t tempted.

3
You get proof

Pass or fail for every check, with the evidence, in a report you can hand to a customer’s security team. When a new escape is published, a new check follows.

Who it’s for

  • Teams that build AI agents and keep getting asked whether the sandbox really holds
  • Teams running their own agent harness that nobody else is testing
  • Pen testers who’ve been asked to test an agent and need checks that are current
