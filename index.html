Finding them first is now the law

The EU’s Cyber Resilience Act covers almost every connected device sold in Europe. Its reporting rules are already in force.

  1. Dec 2024

    The Act enters into force

    Regulation (EU) 2024/2847

    Products with digital elements sold in the EU have to meet security requirements for as long as they’re supported.

  2. Sep 2026

    Reporting begins

    European Commission

    Manufacturers must report actively exploited vulnerabilities in their products, with an early warning within 24 hours.

  3. Dec 2027

    Full obligations apply

    European Commission

    Products must ship without known exploitable vulnerabilities, and manufacturers must handle new ones for the life of the product.

Shipping a known exploitable bug is exactly what the Act rules out. A bug you find yourself is a fix. A bug someone else finds first can be a report to a regulator.

What it looks for

The bug families that keep coming back, release after release, and turn a device into someone else’s device.

Memory bugs
Overflows and use-after-free in the C code that handles outside input: web servers, network services, parsers.
Command injection
Settings fields and admin pages whose input ends up in a shell command.
Secrets and updates
Hard-coded passwords and keys, and update paths that install firmware without checking where it came from.
Old components
Outdated libraries and vendor SDKs inside the image, checked for whether the known bug can actually be reached.

How it works

  1. Send a firmware image

    Start with one image, the same file you ship to devices. No source code needed.

  2. It checks for known bug families

    It unpacks and decompiles the image, looks for the bug families already found in other products and earlier releases, and runs every suspected match in emulation.

  3. You get proof, every release

    Each confirmed bug comes with where it is, the input that triggers it and the crash it causes. Leads that don’t reproduce are dropped, so your team doesn’t chase noise. Then it checks each new release as you ship it.

How we handle your firmware

Firmware is your product. Here’s what we commit to.

  • It stays yours. Never shared, never used to train AI models, and deleted when you ask.
  • It’s analyzed in isolation. Each image runs in its own sealed environment with no outside network access.
  • You hear about bugs first. We never publish or report a bug in your product without your agreement.
  • On your own servers, if you need it. For teams that can’t send firmware out, we’re building a version that runs inside your environment.
