The way out keeps changing

Between July and September 2026, researchers published five separate ways out of popular coding agent sandboxes. Most of them needed no clever prompt.

  1. Jul 2026

    SharedRoot

    Accomplish AI

    A chain of steps gave the agent read and write access to the host computer’s files.

  2. Jul 2026

    Seven findings in four tools

    Pillar Security

    Agents wrote settings files, or used trusted command names, that the unprotected host ran later.

  3. Aug 2026

    GuardFall

    Reported by the Cloud Security Alliance

    Blocked commands could be disguised to slip past the filter in 10 of 11 open-source agents.

  4. Sep 2026

    GitSpawn

    Manifold Security

    A project’s own git settings ran a command outside the sandbox: 8 flaws across 7 agents.

  5. Sep 2026

    DeepSeek Harness escape

    Reported by the Cloud Security Alliance

    The agent could reach the switch that turned its own sandbox off.

These are plumbing bugs, and plumbing can be tested directly. That’s what Husk does.

What Husk checks

Four walls. If any one of them fails, a hijacked agent can do real damage.

Files
Can the agent read or change anything outside its workspace, like your SSH keys or your other projects?
Network
Can it send data out to the internet, or reach services on the machine it should never touch?
Secrets
Does it ever hold a real password or token, or only stand-ins that are useless if stolen?
Its own controls
Can it switch off its own restrictions, or leave something behind that runs later, outside the box?

How it works

  1. Run it inside the box

    Start Husk in the same sandbox your agent uses, on your own machine or in your build pipeline.

  2. It tries every known way out

    Each check copies a published escape and tries it directly. No AI model is in the loop, so a pass means the wall held, not that the agent wasn’t tempted.

  3. You get proof

    Pass or fail for every check, with the evidence, in a report you can hand to a customer’s security team.

Who it’s for

  • Teams that build AI agents and keep getting asked whether the sandbox really holds
  • Teams running their own agent harness that nobody else is testing
  • Pen testers who’ve been asked to test an agent and need checks that are current
